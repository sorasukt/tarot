# แนวทางปรับปรุง sorasukt Tarot

อัปเดตล่าสุด: 28 สิงหาคม 2026

## หลักการด้านเนื้อหาและประสบการณ์ใช้งาน

- ข้อความที่ผู้ใช้เห็นต้องอธิบายสิ่งที่ทำได้และสิ่งที่จะเกิดขึ้นด้วยภาษาธรรมดา ไม่เปิดเผยชื่อ endpoint, prompt, cache, model หรือรายละเอียดการทำงานภายในโดยไม่จำเป็น
- แต่ละหน้าต้องมีเป้าหมายหลักเพียงหนึ่งอย่าง ป้ายกำกับ ช่องกรอก และปุ่มต้องบอกการกระทำได้ทันที
- ใช้รูปแบบ header, navigation, footer, form, result, error และ loading ร่วมกัน เพื่อให้ UX/UI สอดคล้องกันทุกหน้า
- ทุกการประมวลผลที่รอผลจากเครือข่ายต้องแสดง animation พร้อมข้อความสถานะแบบ `aria-live` ปิดปุ่มที่กำลังทำงาน และคืนสถานะปุ่มเมื่อเสร็จ
- ข้อความผลลัพธ์เน้นประโยชน์ต่อผู้ใช้ ส่วนรายละเอียดผู้ให้บริการและการใช้ข้อมูลเก็บไว้ในหน้านโยบายที่เกี่ยวข้อง

## Accessibility

- ใช้ semantic HTML, ชื่อเมนูด้วย `aria-label`, สถานะด้วย `role="status"` หรือ `role="alert"` และเชื่อม dialog กับหัวข้อ/คำอธิบาย
- แสดง focus ที่มองเห็นชัด ใช้งานด้วยแป้นพิมพ์ได้ และกัก focus ไว้ในหน้าต่างยอมรับนโยบาย
- ช่องวันเกิดใช้ `autocomplete="bday"`; ช่องค้นหาสถานที่ใช้รูปแบบ combobox และแจ้งสถานะเปิด/ปิดรายการ
- รองรับ `prefers-reduced-motion` โดยลด animation และ transition

## ความพร้อมใช้งานและการประมวลผล

- Worker ไล่ลองโมเดลภายในคำขอเดียวได้นานสูงสุด 60 วินาที โดยรอแต่ละโมเดลไม่เกิน 10 วินาที ส่วนหน้าเว็บรอได้สูงสุด 65 วินาที
- เมื่อเกิด timeout หรือได้รับสถานะ 504 หน้าเว็บลองส่งคำขอใหม่ให้อัตโนมัติหนึ่งครั้ง ผู้ใช้จึงไม่ต้องกดขอใหม่เอง
- เมื่อโมเดลตอบ 429, 404, 5xx, ใช้เวลานานเกินกำหนด, เชื่อมต่อไม่ได้ หรือคืนผลไม่สมบูรณ์ ระบบจะไปโมเดลถัดไปทันทีภายในคำขอเดิม โดยมี Gemini 3.1 Flash Lite และ Gemini 3.5 Flash Lite เป็นตัวสำรองช่วงท้าย ผู้ใช้ไม่ต้องกดปุ่มใหม่ หากทุกโมเดลใช้ไม่ได้จะแจ้งเหตุผลและแสดงปุ่มสนับสนุนการพัฒนาผ่าน Stripe
- ผลลัพธ์ของสมาชิกที่สร้างสำเร็จบันทึกใน Cloudflare D1 และนำกลับมาใช้เมื่อข้อมูลนำเข้าเดิม เพื่อหลีกเลี่ยงการคำนวณซ้ำ
- หน้าหลักแสดงสีมงคลประจำวันเฉพาะสมาชิกพร้อมข้อความ “สำหรับคุณเท่านั้น” โดยใช้ข้อมูลวันเกิดและผลประจำวันที่บันทึกไว้ใน D1
- เมนูสีมงคลให้เลือกวันที่ระหว่างปี 1900–2100 สมาชิกจะได้รับผลที่ใช้ข้อมูลโปรไฟล์เป็นบริบทเพิ่มเติม และผลเดิมจะถูกนำกลับมาใช้ภายในระยะเวลาเก็บรักษา

## การยอมรับนโยบายและการเก็บข้อมูล

- ก่อนใช้งานครั้งแรก ผู้ใช้ต้องยอมรับข้อกำหนดการใช้บริการและนโยบายความเป็นส่วนตัวเวอร์ชัน `2026-08-28-payments1`
- สมาชิกเก็บหลักฐานการยอมรับใน D1; ผู้ใช้ทั่วไปเก็บเวอร์ชันที่ยอมรับในเบราว์เซอร์
- บันทึกเฉพาะเหตุการณ์ที่จำเป็นต่อการปรับปรุงบริการ ได้แก่ หน้า/ฟีเจอร์ สถานะการทำงาน ระยะเวลา และการใช้ผลเดิม
- ข้อมูลวิเคราะห์ไม่เก็บข้อความคำถาม ค่าที่กรอก หรือวันเกิดซ้ำ ผู้ใช้ทั่วไปใช้ตัวระบุสุ่มที่แปลงเป็นค่าแฮชก่อนบันทึก
- เหตุการณ์ใช้งาน ผลประจำวัน และผลลัพธ์ที่ลดการคำนวณซ้ำหมดอายุภายใน 60 วัน งานตามกำหนดเวลาจะลบข้อมูลหมดอายุทุกวัน

## การชำระเงินและสมาชิกพิเศษ

- Tarot for your daily รองรับแผนรายสัปดาห์ รายเดือน และรายปี โดยเลือก Subscription หรือชำระครั้งเดียวได้
- ราคา Subscription คือ ฿59/สัปดาห์, ฿199/เดือน และ ฿1,690/ปี ส่วน Pay as you go คือ ฿79/สัปดาห์, ฿259/เดือน และ ฿1,790/ปี โดย Worker ตรวจราคา สกุลเงิน ประเภท Price และรอบบิลกับ Stripe ก่อนเปิด Checkout
- PromptPay รองรับเฉพาะ Pay as you go และการสนับสนุนแบบชำระครั้งเดียว ส่วน Subscription ชำระด้วยบัตรเท่านั้น
- หน้าเลือกสมาชิกแสดงโลโก้ Visa, Mastercard, Apple Pay และ Google Pay สำหรับทั้งสองรูปแบบ และเพิ่ม PromptPay สำหรับ Pay as you go โดยกระเป๋าเงินจะแสดงเมื่ออุปกรณ์รองรับ ส่วนหน้าชำระเงินจะเลือกแสดงวิธีอื่นที่เปิดใช้งานและรองรับรายการนั้นโดยอัตโนมัติ
- โลโก้วิธีชำระเงินบนหน้าเลือกสมาชิกใช้ไฟล์อย่างเป็นทางการจาก `tarot/assets/payments` และมีชื่อวิธีชำระเงินสำหรับโปรแกรมอ่านหน้าจอ
- สมาชิกแบบ Subscription เปลี่ยนแพ็กเกจ วิธีชำระเงิน หรือยกเลิกได้จากหน้า “ฉัน” ระบบรับการเปลี่ยนแปลงจาก Webhook และตรวจสถานะล่าสุดอีกครั้งเมื่อผู้ใช้กลับจากหน้าจัดการ เพื่ออัปเดตแพ็กเกจ สถานะ วันสิ้นสุด และการยกเลิกใน D1
- หน้าแผนสมาชิกวางส่วนเปรียบเทียบคุณสมบัติของ Subscription กับ Pay as you go ไว้ก่อนเลือกแผน เมื่อผู้ใช้เลือกวิธีชำระแล้ว การเปรียบเทียบราคาและยอดประหยัดจะแสดงเฉพาะรายสัปดาห์ รายเดือน และรายปีภายในวิธีนั้น ไม่เปรียบเทียบราคาข้ามวิธีชำระ
- Checkout ของแผนสมาชิกเปิดให้กรอก Promotion Code ที่สร้างใน Stripe ได้ทั้ง Subscription และ Pay as you go โดยไม่ใช้ส่วนลดกับยอดสนับสนุนที่ผู้ใช้กำหนดเอง
- ข้อความที่ผู้ใช้เห็นใช้ภาษาทั่วไปและเรียกบริการภายนอกตามหน้าที่ เช่น “ผู้ให้บริการชำระเงิน” โดยไม่เปิดเผยชื่อเทคโนโลยีหรือขั้นตอนภายใน ส่วนการจัดการสมาชิกและการชำระเงินอยู่ในหน้า “ฉัน” เท่านั้น
- หน้าชำระเงินเลือกภาษาตามการตั้งค่าภาษาของเบราว์เซอร์หรืออุปกรณ์ของผู้ใช้โดยอัตโนมัติ
- ทุกหน้าใน Tarot ใช้ visual system เดียวกับหน้าเปิดไพ่ ได้แก่หัวข้อ serif ขนาดใหญ่แบบสองบรรทัด ระยะห่าง เนื้อหาหลัก การ์ด ฟอร์ม และปุ่มที่สอดคล้องกันทั้งเดสก์ท็อปและมือถือ
- ปุ่มส่งต่อจากหน้าสนับสนุนใช้ข้อความ “ดำเนินต่อ” เพื่อให้สั้นและเข้าใจง่าย ก่อนพาผู้ใช้ไปเลือกวิธีชำระบน Stripe
- สิทธิ์สมาชิกอัปเดตจาก Stripe webhook ที่ผ่านการตรวจลายเซ็นเท่านั้น พร้อมป้องกัน event ซ้ำใน D1
- ผู้ใช้เปิด Customer Portal เพื่อแก้ไขวิธีชำระ ดูข้อมูลเรียกเก็บเงิน หรือยกเลิก Subscription ได้
- ระบบสนับสนุนรับจำนวนเงิน 50–100,000 บาท ผ่านบัตรหรือ PromptPay และขอที่อยู่จัดส่งใน Stripe Checkout สำหรับสิ่งตอบแทน
- หน้าขอบคุณตรวจ Checkout Session จาก Worker และแสดงลิงก์ใบเสร็จจาก Stripe เมื่อมี
- D1 ไม่เก็บเลขบัตร CVC หรือที่อยู่ฉบับเต็ม แต่เก็บหมายเลขอ้างอิง สถานะชำระ สิทธิ์สมาชิก และสถานะจัดส่งที่จำเป็น
